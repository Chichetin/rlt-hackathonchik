# Интерфейс и сценарий демо (= e2e)

Источник: раздел 10 `docs/source/hackathon-research-workflow.md`. Урок прошлого хакатона:
интерфейс, отдельный критерий оценки, пришёл в `main` последним. Здесь **UI строится против
заглушки API с первого часа, а e2e демо существует с первого коммита** и растёт вместе с продуктом.

## Пользователь

По умолчанию — **контрактный управляющий заказчика СПб** **[ПРОВЕРИТЬ]** `[СПРОСИТЬ Q-07]`: не
аналитик, работает в АИС ГЗ, торопится. Вопрос «для какой задачи подбор» (пригласить в закупку
малого объёма, собрать КП для НМЦК, найти производителя вместо посредника) — open question в
`research/PROBLEM.md`.

## Сценарий демо — 60–90 секунд

1. Ввёл номер закупки (lot_id или реестровый номер, `GET /api/lot/{номер}`, D-027) — запрос, НМЦК и заказчик заполняются из извещения; либо ввёл наименование товара или позиции из ТЗ. Нет данных/лота — сообщение и ввод текстом.
2. Увидел два блока: **«С опытом госзакупок»** и **«Новые из открытых источников»**; у каждого
   поставщика — score и объяснение в одну строку.
3. Открыл карточку: компоненты скоринга, факты с источниками и датами, контакты, тип
   (производитель или дистрибьютор), статус МСП, проверка РНП. Блок «Отзывы» (D-066): пометка «не влияет на
   оценку подбора» и ссылки на поиск отзывов по названию + ИНН; рейтинг из отзывов не показываем — нет
   источника, который можно честно проверить.
4. Включил фильтры (только МСП, только производители, регион). Фильтр оставляет только
   подтверждённые совпадения (D-030): регион — по реестру, иначе по КПП (78/47); если МСП или тип
   у кандидатов ещё не известны (до обогащения), UI пишет «Тип поставщика ещё не определён у N из M
   — признак появится после обогащения», а не «никого не нашли». Если роль определена правилом, но
   это не производство и не торговля (`kind = unknown`, основание — в карточке), текст другой: «основной
   ОКВЭД — не производство и не торговля: такая компания производителем не считается». Если «Только
   производители» опустошил блок «Новые», UI пишет, что среди них нет производителей по основному
   ОКВЭД (или что подтверждённых производителей нет, а у N из M роль ещё не определена), а не «тип не подтверждён» (D-057).
5. Выгрузил список в Excel. **[ПРОВЕРИТЬ]** Если эксперты подтвердят сценарий сбора КП — кнопка
   «Сформировать запрос КП» выбранным поставщикам.

Сценарий закреплён в `src/ui/e2e/demo.spec.ts` (`make e2e`) шаг в шаг. **PR, ломающий его, не
вливается.** Область, подключившая свою часть к реальным данным, добавляет в него шаг (например,
проверку, что у карточки есть факт из открытого источника с URL). Демо-запрос (задача T-05) —
реальная закупка СПб из данных организаторов.

## Требования

- Выдача за секунды; время запроса меряется и попадает в `pitch/facts.md` командой.
- Ввод не требует знания ОКПД2 (коды показываются, но не обязательны).
- У каждого действия — состояния загрузки, результата, пустого результата и ошибки; ошибка API не
  выглядит как успех.
- Факт без источника не показывается; у ИНН без подтверждения — «ИНН не подтверждён».
- Пока путь на заглушке — плашка «демонстрационные данные» (`SearchResponse.stub`).
- Веса компонент видны в карточке (`value × weight`); пресеты весов — если хватит времени.

### Фильтры на сервере (#232, D-086)

Ключи `Query.filters` читает `src/match/filters.py` (контракт не меняется); фильтры действуют по И, до
страницы и до выгрузки Excel, юр. статус (ликвидация, РНП) отсекается всегда:

- `kinds` — роли через запятую: `manufacturer`, `distributor`, `dealer`, `unknown`. `unknown` — «Роль не
  определена»: правило дало `unknown` (D-057) или роли ещё нет. Пусто — без фильтра. `only_manufacturers: true` —
  синоним `kinds=manufacturer` (e2e и старые клиенты), вместе с `kinds` — по И.
- `entity` — `ul` (ЮЛ) или `ip` (ИП): по `stats.entity_type` данных организаторов, иначе по длине ИНН (10 / 12);
  без ИНН строка под фильтр не попадает — не угадываем.
- `min_score` — минимальная релевантность: строки со score ниже порога скрыты (score сервера; локальные веса
  «Настроек», D-079, его не меняют).
- `only_msp`, `region` — как раньше (D-030).

Неверное значение (`kinds=producer`, `entity=fl`, `min_score=high`) — 422 с именем поля, а не молча выключенный
фильтр. Счётчики для чипов — заголовок `X-Facets` ответа `/api/search`, JSON в ASCII (пример — синтетическая
фикстура тестов, запрос «бумага А4», `tests/unit/test_discover.py`):

```json
{"history": {"kind": {"manufacturer": 0, "distributor": 0, "dealer": 0, "unknown": 6},
             "entity": {"ul": 4, "ip": 2, "unknown": 0}},
 "discovered": {"kind": {"manufacturer": 0, "distributor": 1, "dealer": 0, "unknown": 0},
                "entity": {"ul": 1, "ip": 0, "unknown": 0}}}
```

Считается по кандидатам блока после юр. статуса; каждая группа — **после фильтров остальных групп** (ревью #240,
D-089): роли — с учётом ЮЛ/ИП, релевантности, МСП, региона и «Может работать у заказчика», но без выбора роли;
ЮЛ/ИП — без `entity`; `near` — без `near_customer`. Число на чипе — сколько строк будет в блоке, если выбрать этот
чип при уже включённых остальных фильтрах; выбор внутри группы её счётчики не меняет; страница не влияет. У «Новых» блок не больше 10 компаний (`discover.MAX_SHOWN`), счётчики ограничены тем же числом.
`entity.unknown` — у скольких ЮЛ/ИП неизвестен (для подписи «признак неизвестен у N»). В Excel — колонки
«Роль» (Производитель / Дистрибьютор / Дилер / Роль не определена) и «ЮЛ/ИП».

### «Может работать у заказчика» и тип закупки (#242, D-089)

Важен регион **заказчика**: товар везут откуда угодно, работы и услуги выполняют на месте. Тип закупки — одна
функция `src/match/purchase_type.py` (правило #188: класс ОКПД2 01–33 — товар, 41–43 — работа, остальное — услуга;
несколько кодов — по большинству, при равенстве работа > услуга > товар). Ключ `near_customer`:

- `worked` — «уже работал с заказчиками региона»: поставщик в регионе заказчика или (заказчик в СПб) участвовал в
  лотах заказчиков СПб (`stats.customers_spb > 0`); у «Новых» — регион по реестру = регион заказчика;
- `near` — «в регионе заказчика или соседнем» (СПб ↔ ЛО); регион поставщика — по реестру, иначе по КПП, у ИП — по ИНН;
- `any` или пусто — любой; `auto` — по типу закупки: `near` для работ и услуг, `any` для товаров и без ОКПД2.

Регион заказчика — по ИНН заказчика (78 / 47), иначе `Query.region` (D-083): без ИНН UI шлёт выбранный регион
заказчика. Поставщик с неизвестным регионом под `worked` / `near` не попадает. Счётчики — `X-Facets`, группа
`near: {"worked": n, "near": n}` в каждом блоке (после остальных фильтров, как выше). Что сервер принял за заказчика и тип закупки — заголовок
`X-Search-Context` (JSON в ASCII), для плашки «Заказчик: … · Тип закупки: … (по ОКПД2 …)»:

```json
{"customer_region": "Санкт-Петербург", "customer_basis": "ИНН 78…", "purchase_type": "services",
 "purchase_label": "услуга", "type_basis": ["81.21.10.000", "81.22.11.000", "81.29.11.000"],
 "default_near": "near", "applied_near": "near"}
```

`customer_basis` — `"ИНН 78…"` (или `"ИНН 47…"`) либо `"регион запроса"`; без ОКПД2 `purchase_type` и
`purchase_label` — `null`, `type_basis` — `[]`, `default_near` — `any`. `applied_near` — что фильтр применил на
самом деле (для `auto` — значение по типу закупки).

## UI-гейт (облегчённый)

1. До кода — скилл `frontend-design`: короткий бриф (задача, состояния, иерархия, viewport).
2. После — Playwright-снимок сценария (`make e2e`, trace при падении) и скилл
   `web-design-guidelines`; снимки — не больше 4 на задачу, в описание PR.
3. Перед чек-поинтом — `operator` проходит сценарий в роли пользователя.

## Страницы и движение (#184)

`/` — один HERO с фоном Pattern Waves (пресет Silk из React Bits), без общей
рамки, sidebar, нижних секций и footer. Навигация сверху на всех размерах экрана;
капсула выбранного раздела плавно переходит между ссылками. «Начать подбор» ведёт
на `/search`, «Как работает подбор» — на `/about`. Shortcut #172 сохранён:
первый скролл вниз с верха главной открывает подбор.

`/search` — форма на приглушённом фоне Micro Slats. `/results`, `/settings`,
`/about` сохраняют обычную прокрутку и однотонный тёмный фон. Стекло остаётся у
отдельных форм, карточек и меню. Кнопок паузы и выбора рисунка нет — прямое указание
пользователя; reduced motion, скрытая вкладка и уход с экрана останавливают фон.

Оба компонента React Bits включены в `src/ui/src/vendor/react-bits` с исходной
лицензией и версией источника. Зависимость OGL. Шейдеры не изменены; при недоступном
WebGL выводится неподвижная CSS-фактура. Изменение reduced motion учитывается без
перезагрузки. Фотографий и Inter нет.

Примеры закупок выбираются колесом с кнопками, ↑/↓ и Home/End; Enter подтверждает
выбор и возвращает фокус в описание. Счётчики используют данные API, подсказки
меню открываются по наведению/фокусу и закрываются Escape. Проверки оболочки:
`src/ui/e2e/glass.spec.ts`, движения и навигации — `micro.spec.ts`, `navigation.spec.ts`.

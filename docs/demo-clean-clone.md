# Демо с чистого клона: откуда данные

`make demo` (проверено на `git clone` в пустой каталог, #13) выбирает данные так (`scripts/demo.sh`):

1. `data/processed/manifest.json` есть — используем готовые parquet.
2. Иначе в `data/raw/` лежат `Извещения*.csv`, `Поставщики*.csv`, `ТРУ*.csv` организаторов
   («Данные 24-25», вне git) — собираем parquet: `python -m src.ingest.build` (минуты на ≈ 680 МБ).
3. Иначе — **синтетическая фикстура** `tests/fixtures/ingest` (`DEMO_FIXTURE=1`): `/api/health`
   отдаёт `stub: true`, UI показывает плашку «Демонстрационные данные». Для проверки запуска, не для показа жюри.

Где взять: данные — **`make data`**: скачивает ассеты релиза `data-2026-10-01` этого репозитория (готовые parquet в
`data/processed/` и CSV организаторов в `data/raw/`), сверяет SHA256, повторный запуск ничего не качает заново; нужен
`gh` с доступом к репозиторию (`gh auth login`). `make data PART=processed` — только parquet (216 МБ, хватает для
`make demo` и `make eval`), `PART=raw` — только CSV (zip 102 МБ → 680 МБ). Без доступа — CSV у организаторов
(копировать в `data/raw/`; DATA_RAW_DIR меняет путь);
индексы BM25 строятся при старте (`python -m src.match.index`, `indexes/`); кеш внешних источников
`cache/` — SQLite, в git нет, на машине показа переносится копированием каталога `cache/`
(запросы и названия из кеша отвечают без сети). Основной путь с Postgres — `make up` (D-035).

Проверка: `make demo` → `curl localhost:8000/api/health` (`status: ok`) → поиск в UI.
Скриншоты: `BASE=http://127.0.0.1:8000 node scripts/screenshots.mjs [лот]` → `pitch/screenshots/`.

## Запасной статический стенд без API (#283, D-131)

Если на машине показа не поднимается ни `make up`, ни `make demo`, остаётся статический стенд: тот же интерфейс,
но ответы API сняты заранее и лежат рядом с `index.html`.

```bash
make static-demo                                   # снять ответы (кеш, без сети) и собрать dist-static/
uv run python scripts/serve_static.py dist-static  # http://127.0.0.1:8080, любой путь → index.html
```

- Что работает: три примера запроса из колеса на главной, 8 реальных закупок из `eval/cases/real.jsonl` по номеру
  (выдача, карточки, «Проверить на истории»), названия классов ОКПД2. Плашка «Демонстрационные данные: статический
  стенд без сервера» видна всегда.
- Что не работает и честно говорит об этом: фильтры — «Фильтры недоступны в статическом стенде» (ответ записан
  без них; снимите фильтр), оценки, тестовая выгрузка; кнопки «Выгрузить в Excel» в стенде нет; другой запрос
  получает список доступных. «Проверить на истории» для лота, который проверить нельзя, отвечает той же причиной,
  что сервис.
- Снимать на машине с прогретым кешем: блок «Новые» и названия компаний берутся из кеша источников
  (`DISCOVERY_OFFLINE=1`), в облачной сессии без кеша там пусто и вместо названий — ИНН.
- `dist-static/` и `cache/static-demo/` — вне git: в них данные организаторов. **Публикация стенда наружу (хостинг,
  домен) — внешнее действие, подтверждение человека №4.**

# Как работает наш сервис — простыми словами

Документ для команды: что где лежит и что происходит, когда пользователь нажимает «Найти поставщиков».
Подробности и обоснования — в файлах из раздела «Где читать подробнее» в конце. Состояние — `main` на 02.10.2026.

## 1. Что делает сервис

Контрактный управляющий заказчика из Петербурга пишет, что хочет купить, например «бумага офисная А4».
Сервис отвечает списком компаний, которых стоит позвать в закупку, двумя группами:

- **«С опытом госзакупок»** — компании, которые уже участвовали в похожих закупках СПб (из данных организаторов);
- **«Новые из открытых источников»** — компании, которых в этих данных нет, но они подходят по профилю
  (из государственных реестров).

У каждой компании видно, **почему она в списке** (оценка по критериям) и **откуда каждый факт** (ссылка и дата).
Список можно отфильтровать и выгрузить в Excel.

## 2. Из чего состоит

```text
  Браузер (интерфейс)
        │  запрос «что купить»
        ▼
  Сервер API ───────────────► Подбор по истории ─────► группа «С опытом госзакупок»
        │                      (данные организаторов)
        ├───────────────────► Поиск новых компаний ──► группа «Новые»
        │                      (реестры ФНС, ГИСП, ЕАЭС, Яндекс)
        │
        └─ «узнать о компании подробнее» ──► Очередь задач ──► Воркер ──► Сайты реестров
                                                                  │
                                              Кеш на диске ◄──────┘
                                     (все ответы сайтов сохраняются;
                                      демо работает без интернета)
```

| Часть | Где в коде | Что делает, простыми словами |
|---|---|---|
| Интерфейс | `src/ui/` | Страница в браузере: форма, две группы, карточка компании, фильтры, выгрузка |
| Сервер API | `src/api/` | Принимает запросы от интерфейса (или от другой системы) и отдаёт ответы |
| Подбор по истории | `src/match/` | Ищет похожие прошлые закупки, ставит компаниям балл, расставляет по порядку |
| Поиск новых | `src/enrich/discover.py` | Ищет подходящие компании в реестрах, которых нет в наших данных |
| Обогащение | `src/enrich/enrich.py`, `src/sources/` | Собирает о компании факты из открытых реестров: название, статус, адрес, роль |
| Очередь и воркер | `src/worker/` | Фоновый процесс: по очереди ходит на сайты реестров, не задерживая ответ пользователю |
| Кеш | `src/sources/cache.py` | Сохраняет на диск каждый ответ сайта (на 7 суток, `SOURCE_CACHE_TTL_S` в `src/settings.py`), поэтому повторно туда не ходим |
| Проверка фактов | `src/enrich/evidence.py` | Пропускает только факты, которые реально есть на сохранённой странице |
| Контракты | `src/contracts.py` | Описание всех данных, которыми обмениваются части; из него делается описание API |
| Загрузка данных | `src/ingest/`, `src/db/` | Превращает CSV организаторов в быстрые таблицы и загружает их в базу |
| Оценка качества | `src/eval/` | Проверяет на прошлых закупках, насколько хорошо мы угадываем участников |

## 3. На каких данных

Организаторы дали три таблицы закупок СПб за 2024–2025 годы:

- **Извещения** — сама закупка: дата, начальная цена (НМЦК), предмет, заказчик, канал (Электронный магазин или АИС ГЗ);
- **Поставщики** — кто участвовал в закупке и кто победил (только ИНН);
- **Позиции** — что именно покупали, с кодом товара (ОКПД2).

После загрузки: **604 452 закупки, 1 010 107 участий, 2 550 089 позиций, 44 196 поставщиков**
(`data/processed/manifest.json`, см. `pitch/architecture.md`, раздел 3.1).

Чего в данных **нет**: названий и контактов компаний, цены контракта, исполнения. Поэтому названия, статусы,
адреса и роли мы берём из открытых государственных реестров (раздел 6).

## 4. Путь одного запроса: «С опытом госзакупок»

1. **Ввод.** Пользователь пишет название товара и/или код ОКПД2. Можно открыть ссылку `/search?lot=<номер>`:
   сервис сам подставит предмет, цену и заказчика из этой закупки и сразу начнёт поиск.
2. **Понимаем запрос.** Исправляем опечатки и раскладку. Если код товара не указан, угадываем его по самым
   похожим прошлым позициям: так класс определяется верно примерно в 82 % случаев (D-110). В интерфейсе
   прямо написано, что класс определён автоматически.
3. **Ищем кандидатов.** Сравниваем слова запроса с названиями позиций всех прошлых закупок, как это делает
   обычный поисковик (по совпадению слов). Компании, которые участвовали в самых похожих закупках, становятся
   кандидатами, всего до 200 (`CANDIDATES` в `src/match/search.py`).
4. **Отсекаем.** Убираем недействующие компании, тех, кто в реестре недобросовестных поставщиков, и всё, что
   отсёк пользователь фильтрами («только малый бизнес», регион, роль). Если признак у компании неизвестен,
   мы не угадываем, а честно пишем, у скольких он неизвестен.
5. **Ставим балл.** Каждой компании — балл от 0 до 1 по шести понятным критериям (веса — `configs/search.yaml`):

   | Критерий | Вес | Что значит |
   |---|---|---|
   | Соответствие товару | 0.40 | Насколько её прошлые позиции похожи на запрос (по словам и по коду товара) |
   | Опыт | 0.20 | Сколько раз участвовала и побеждала в закупках с похожими позициями |
   | Надёжность | 0.15 | Доля побед, повторные победы у тех же заказчиков, число заказчиков, стаж |
   | Активность | 0.10 | Как давно участвовала в последний раз (ответит ли на приглашение) |
   | География | 0.07 | В регионе заказчика или рядом |
   | Цена | 0.08 | Подходит ли размер закупки к её обычным закупкам |

   Если цена закупки не указана, вес «Цены» делится между остальными критериями (D-198).
   **Балл — это ровно взвешенная сумма критериев**, её видно в карточке компании.
6. **Расставляем по порядку.**
   - **Если указан заказчик** (его ИНН), порядок задаёт обученная модель. Это «набор деревьев решений»,
     который на истории закупок СПб научился угадывать, кто реально придёт в закупку. Она смотрит на 44 признака (`feature_names` в
     `models/ranker/R-long-gbm.txt`):
     те же критерии плюс, например, сколько раз компания работала именно с этим заказчиком. Модель обучена
     только на прошлом: на закупках до 1 июля 2025 года, без подглядывания в проверочные данные (D-171).
     Без модели (нет файла или библиотеки) порядок тоже задаёт формула.
   - **Если заказчика нет**, порядок задаёт сама формула балла. Модель учили на запросах с заказчиком, и без
     него она работает хуже обычного текстового поиска (D-172).
7. **Объясняем.** У каждой компании видна разбивка балла по шести критериям. Когда порядок задаёт модель,
   ещё видно, какие признаки подняли компанию выше всего и какой тянул вниз, и строка «выше следующего: …» —
   чем она лучше той, что ниже. Это точный расчёт вклада каждого признака в решение модели, а не догадка.

## 5. Путь одного запроса: «Новые из открытых источников»

Задача — найти компании, которых **нет** в данных организаторов, но которые подходят по профилю.

1. **Код товара → вид деятельности.** Из кода товара (ОКПД2) получаем подходящие коды деятельности компании
   (ОКВЭД): «производит это» и для товаров ещё «торгует этим оптом». Эта таблица соответствия — наше правило,
   и её видно пользователю.
2. **Реестр малого и среднего бизнеса ФНС.** Ищем там компании Петербурга и Ленобласти с таким основным
   видом деятельности. Есть два пути: живые запросы к сайту ФНС и офлайн-копия всего реестра (6,77 млн
   компаний по замеру D-181, скачивается отдельно — `make data PART=pool`).
3. **Компании, найденные заранее веб-поиском** (123 строки, `configs/leads/`, включено по умолчанию —
   `DISCOVERY_LEADS`). Попадают в список, только если ИНН проходит проверку и в кеше есть карточка ФНС;
   иначе ИНН встаёт в очередь на обогащение.
4. **ГИСП (реестр российской промышленной продукции Минпромторга).** Если у компании там есть продукция с
   нашим кодом товара, это сильный довод: «производит этот товар по реестру Минпромторга», роль — производитель.
   Через ГИСП в группу могут попасть и компании, которых нет в реестре малого бизнеса.
5. **Компании стран ЕАЭС.** 22 проверенные компании (21 из Беларуси, 1 из Армении, `configs/eaeu/leads.csv`),
   у каждой ссылка на государственный реестр её страны (D-185).
6. **Яндекс-поиск (запасной путь).** По умолчанию **выключен**: работает, только если на машине заданы ключ и
   лимиты запросов (`YANDEX_*` в `src/settings.py`, это платно). Тогда включается сам, если сильных кандидатов
   (соответствие товару ≥ 0.8) меньше пяти, и добирает до пяти (D-193).
   Ещё есть кнопка «Искать в реальном времени». Компания из Яндекса попадает в список, только если её ИНН
   нашёлся на её собственном сайте и подтвердился карточкой ФНС. Сниппет из выдачи фактом не считается.
7. **Отсекаем.** После всех каналов убираем тех, кто уже есть в данных организаторов (они — в группе
   «С опытом»), ликвидированных, тех, кто в реестре недобросовестных поставщиков, и всё, что отсекли фильтры
   пользователя.

Показываются **все** найденные компании после фильтров (до 200, `block.max_shown` в `configs/discover.yaml`;
компании ЕАЭС добавляются сверх этого), первые десять — вперемешку производители и оптовики (D-193).

## 6. Карточка компании: откуда факты

Когда компания попала в выдачу, мы собираем о ней факты. Порядок источников:

1. **«Прозрачный бизнес» ФНС (pb.nalog.ru)** — самая полная карточка: наименование, ОГРН, статус, адрес,
   основной вид деятельности, категория малого бизнеса. Сайт иногда просит капчу; мы решаем её автоматически,
   если задано `PB_CAPTCHA_SOLVE=1`. В `make up` это включено по умолчанию, в `make api` и тестах выключено
   (D-177, D-190).
2. Если не получилось — **реестр малого и среднего бизнеса**, потом **бухгалтерская отчётность ФНС (ГИР БО)**.
   Фактов меньше, но у каждого свой источник.
3. Сверху добавляем:
   - реестр недобросовестных поставщиков (ЕИС);
   - открытые данные ФНС: численность, доходы и расходы, налоговый режим, недоимка;
   - ГИСП (производит ли компания продукцию);
   - НОСТРОЙ (допуск к строительным работам);
   - из данных организаторов: статистику участий и с кем компания подаёт совместные заявки.

**Роль компании** (производитель / дистрибьютор / дилер) определяем правилом, без угадывания:

- по основному виду деятельности (D-057): производство (коды 10–32) — производитель, оптовая торговля — дистрибьютор,
  розница и агенты — дилер;
- продукция в ГИСП — производитель по государственному реестру;
- второе основание — поведение в данных: если компания поставляет очень разное (15+ классов товаров, и на
  главный приходится меньше 30 %), пишем «по истории закупок похожа на посредника» (D-200).

Основание роли всегда показывается в карточке.

**Главное правило фактов.** Каждый факт показывается вместе со ссылкой на страницу и датой, когда она
загружена. Значение факта должно **дословно** встречаться в сохранённом тексте этой страницы, а ИНН
проверяется по контрольным цифрам. Нет источника — факт не показываем. Ничего не выдумываем.

**Почему поиск не тормозит.** Сам запрос пользователя за карточками в интернет не ходит. Он берёт то, что
уже есть в кеше, а остальные компании ставит в очередь. Воркер в фоне обходит сайты с паузами, чтобы нас не
заблокировали, и сохраняет каждый ответ в кеш. Кеш — один файл на диске, и демо на нём работает без интернета.

## 7. Как мы проверяем, что подбор хороший

Идея простая: берём прошлую закупку, прячем от сервиса её участников и смотрим, попали ли они в нашу первую
десятку.

- Данные делим **по времени**. На закупках до 1 июля 2025 года всё настраиваем и учим. Проверяем на 2 000
  закупках июля–сентября 2025 года (`eval/cases/dev.jsonl`). Закупки с 1 октября 2025 года «запечатаны»: их проверяем один раз в самом
  конце, чтобы не подогнать результат (`configs/split.yaml`, `research/EVAL.md`).
- Каждая цифра получается командой `make eval EXP=<имя>`, которая пишет файл с результатом. Цифры для
  слайдов — только из `pitch/facts.md`, со ссылкой на такой файл.
- Сейчас (F-43): в среднем **59 % участников закупки оказываются в нашей первой десятке**. У подбора «кто уже
  работал с этим заказчиком» — 39 %, у простого поиска по словам — 45 %. Компаний, **новых для заказчика**,
  мы находим в 3 раза больше. Это замер для запросов с заказчиком, подробности и оговорки — в `pitch/facts.md`, F-43.

## 8. Как запускается

| Режим | Команда | Что внутри |
|---|---|---|
| Демо без Docker | `make demo` | Данные из файлов на диске, поиск по словам, API + воркер. Основной запасной путь |
| Полная схема | `make up` | Docker: база Postgres, API, воркер. Docker на нашей машине — внутри WSL Ubuntu-24.04; там нет автозапуска, демон Docker стартуем вручную (комментарий в #547) |

Данные организаторов и снимок кеша скачиваются командой `make data` (см. `README.md`). Без них `make demo`
поднимается на демонстрационных данных с плашкой об этом.

## 9. Что работает, а что — план

| Что | Статус |
|---|---|
| Подбор, две группы, карточка с источниками, фильтры, выгрузка в Excel | работает |
| Ссылка `/search?lot=<номер>` — открыть подбор по конкретной закупке | работает |
| Описание API для встраивания в АИС ГЗ (`docs/openapi.json`) | есть |
| Кнопка «Подобрать поставщиков» прямо в карточке закупки АИС ГЗ | план: её добавляет владелец системы |
| Несколько воркеров на разных машинах с общим кешем | план: кеш сейчас — файл на одной машине |
| Автоматическое обновление реестров и новых закупок по расписанию | план |
| Языковые модели (LLM) в продукте | не используются: всё работает без них |

## 10. Словарик

| Слово | Что это |
|---|---|
| АИС ГЗ | Региональная система госзаказа Петербурга; в неё встраивается наш сервис |
| ЭМ | Электронный магазин — закупки малого объёма в АИС ГЗ |
| НМЦК | Начальная (максимальная) цена закупки |
| ИНН | Номер налогоплательщика; по нему мы склеиваем данные из разных источников |
| ОКПД2 | Код товара или услуги («что покупают») |
| ОКВЭД | Код вида деятельности компании («чем занимается») |
| МСП | Малый и средний бизнес; у ФНС есть открытый реестр таких компаний |
| РНП | Реестр недобросовестных поставщиков — кто срывал контракты |
| ГИСП | Реестр российской промышленной продукции Минпромторга: кто что производит |
| ЕАЭС | Евразийский экономический союз (Беларусь, Армения, Казахстан, Киргизия) |
| API | «Вход» в сервис для программ: через него ходит наш интерфейс, через него же может ходить АИС ГЗ |
| Воркер | Фоновый процесс, который по очереди выполняет долгие задачи (сходить на сайт реестра) |
| Кеш | Сохранённые на диск ответы сайтов: второй раз за тем же не ходим, демо работает без сети |
| Балл | Взвешенная сумма шести критериев, от 0 до 1 |
| Ранжировщик | Обученная модель, которая расставляет компании по порядку, когда известен заказчик |

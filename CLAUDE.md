## Что считается победой (раздел 0)

АИС ГЗ — региональная система госзаказа СПб: Портал 44, Портал 223 и Электронный магазин (закупки
малого объёма, п. 4, 5 ч. 1 ст. 93 44-ФЗ; данные публичны на estore.gz-spb.ru). В жюри — директор
СПб ГБУ «ИМЦ» (техподдержка АИС ГЗ) и заместитель председателя Комитета по госзаказу СПб: будущие
пользователи и владелец системы, в которую решение встраивается.

Жюри должно увидеть, что сервис **работает на реальных данных**, **находит больше и лучше, чем
заказчик нашёл бы сам**, **объясняет каждую рекомендацию и происхождение каждого факта** и
**понятно встраивается в АИС ГЗ**.

**Сначала работающий end-to-end, потом измеримое качество, потом полировка. Прозрачность важнее
изощрённости.**

**Критерии жюри — 100 баллов** (слайд организаторов, `docs/source/evaluation-criteria.md`).

## Задачи и координация (раздел 2, переписан под Issues)

- **Роли DATA, MATCH, SOURCES, APP — это метки `area:data|match|sources|app`** и карта владения
  каталогами `docs/project-structure.md`. У области есть основной человек, но **любой может взять
  свободную задачу чужой области**, если там никто не работает.
- **Задачи — GitHub Issues.** Взять = назначить себя: `bash scripts/issues.sh take <N>`. Остальное:
  `free`, `mine`, `board`, `create`, `check`, `note` (`bash scripts/issues.sh` — справка).
- **Занятость мягкая.** `take` при занятой той же `area:` не отказывает, а предупреждает, кто и с
  какого времени — договоритесь по файлам. Чужую задачу **без движения > 45 минут** (обновление
  issue, её PR или коммит в её ветке) `take` перехватывает сам с комментарием «перехвачена … без
  движения с …, ветка …». **Прямое указание человека «возьми #N» выполняется всегда**:
  `take <N> --force`, тоже с комментарием. Перехват = продолжение чужой ветки, не переписывание.
- **Правка без взятой задачи — жёсткий запрет.** Ни одной правки файла, коммита или push, пока
  задача #N не назначена на тебя и не открыт worktree `.claude/worktrees/<N>-<тема>` на ветке
  `worktree-<N>-<тема>`. Нет задачи — `issues.sh create`, потом работай; это касается и одной
  строки в документе. Держат хук `check-issue.sh` (PreToolUse) и `.githooks/pre-commit`,
  `pre-push` (для людей). Исключение — файлы вне репозитория (scratchpad агента).
- **`status/*.md` нет.** Память агента при сжатии контекста — комментарий в задаче:
  `issues.sh note <N> "<сделано>" "<дальше>" "<блокер|нет>"` перед `/compact`, `/clear`, концом
  сессии и закрытием задачи. Перед новой задачей — `issues.sh board` (его же показывает хук).
- **`blocker`** — риск демо или сдачи, не закрытый в этом ходе: задача с этой меткой сейчас же.
  Открытые `blocker` показывает `session-context.sh`; они раньше своей задачи.
- **Шаблон задачи** — `.github/ISSUE_TEMPLATE/task.md`: цель → пункт условий → критерий приёмки
  (команда) → «Зависит от #…» → **сложность и рекомендуемая модель** (запускать ли `builder` на opus).
- **Контракты** — `src/contracts.py`, единственная точка стыковки ролей; OpenAPI и TS-типы UI
  генерируются из него (`make openapi`, расхождение ловит `make check`). Замораживаются 01.10 в
  11:30 (подтверждение человека №1); дальше изменение — отдельный PR с меткой `contract` и
  перечнем потребителей (`grep -rn "<Тип>" src tests`). Молча под свой модуль не меняется.

## Автономия: агент аппрувит сам, через субагентов

- Решение по реализации, трактовке, методу, контракту агент **не ждёт от человека**: формулирует →
  проверяет свежим субагентом (`reviewer` в режиме «решение» или скептик с контекстом только из
  diff и условий) → «принять» — строка в `research/DECISIONS.md` и дальше; «отклонить» — исправить
  и повторить; два отклонения подряд — арбитр `jury`.
- PR вливается после вердикта `reviewer` «merge» и зелёного `make check` (и `make e2e`, если
  затронут API или UI), по одному.
- **Подтверждение человека — только для пяти вещей:** (1) заморозка контрактов (01.10, 11:30);
  (2) план задач после kickoff; (3) изменение методологии скоринга — формула, состав компонент
  (это слайд); (4) всё внешнее — массовый парсинг сайтов, регистрация в сервисах, платные API;
  (5) feature freeze и code freeze.
- Массовые LLM-вызовы через сессию разрешены (Claude Max). Остаётся: сначала подвыборка, потом весь
  объём; одна модель не ранжирует и не судит одновременно.
- Застрял на баге > 20 минут — сначала скилл `diagnose` в свежем субагенте, к человеку — если не
  помогло.

## Стек — предварительный (D-003)

Это **стартовая ставка, а не решение**. Kickoff обязан сверить стек с условиями и данными; если
видно, что иначе лучше (другая БД, Streamlit вместо React, другой поиск, отказ от docker-compose),
— **можно и нужно менять** с записью в `research/DECISIONS.md`. Держаться за стек «потому что так в
каркасе» запрещено.

- Python 3.12, `uv` + `uv.lock`, FastAPI, pydantic v2 (`src/contracts.py`). Основная БД — Postgres
  (`make up`, `make db-load`), векторы — pgvector + HNSW (D-054, D-033); по умолчанию `retriever: bm25`,
  `pg_hybrid` — только после eval и подтверждения №3 (D-034). DuckDB — ETL и аналитика, а также запасное
  хранилище `make demo` без Docker (`ParquetStore`, D-051);
  поиск — `bm25s`; эмбеддинги — `sentence-transformers` (`make setup-ml`, модели — `make
  models`, e5 с префиксами `query: `/`passage: `); кеш внешних источников — SQLite с TTL
  (`src/sources/cache.py`).
- docker-compose: `api`, `worker`, `db`; очередь обогащения — таблица задач + процесс `worker`
  (`src/worker/`), без Celery; Redis — только если замер покажет, что индексов Postgres не хватает
  (D-024). Пагинация, сортировка, фильтры и выгрузка — на сервере (D-024). `make demo` без Docker
  (D-007) — запасной путь на parquet + BM25, основной — `make up` (D-035).
- Фронт — React + Vite + TypeScript (`src/ui/`), строится против заглушки API с первого часа.
- LLM в продукте — за интерфейсом провайдера из `.env` (`src/llm/provider.py`), **режим без LLM
  обязателен**; разрешённые провайдеры `[СПРОСИТЬ Q-13]`; названия моделей и адреса API — из
  актуальной документации провайдера, не из памяти.
- Тесты: pytest, Vitest, Playwright. **Один e2e — сценарий демо** (`src/ui/e2e/demo.spec.ts`,
  `docs/ui.md`): запрос → два блока → карточка с компонентами и источниками → фильтр → выгрузка.
  Растёт вместе с продуктом; **PR, ломающий его, не вливается.**
- Команды: `make setup`, `make check` (lint, typecheck, pytest, vitest, хуки, OpenAPI, `# STUB`),
  `make demo`, `make e2e`, `make eval EXP=<id>`, `make eval-final CONFIRM=<sha256>`, `make up`.

## Проверки кодом, а не словами

- **Evidence** (`src/enrich/evidence.py`, тест на честной и выдуманной карточке): у каждого
  `Evidence` есть `url` и `fetched_at`; извлечённое значение (ИНН, телефон, email, адрес) буквально
  есть в тексте закешированной страницы; ИНН проходит контрольные цифры. Факт без источника не
  показывается. LLM **извлекает**, но не **порождает**: выдуманный ИНН/контакт — блокер.
- **Stub** помечен `# STUB` и пишет предупреждение в лог. `make stubs`: предупреждение до code
  freeze, ошибка после. UI показывает плашку «демонстрационные данные», пока путь на заглушке.
- **Запечатанный backtest**: split по времени (`configs/split.yaml`); holdout читает только `make
  eval-final` — sha256 конфигурации, чистое дерево, один запуск на конфигурацию, запись в
  `eval/final-log.md` (D-010). Правила оценки — `research/EVAL.md`.
- `make eval EXP=<id>` пишет `eval/results/<id>.json` (конфиг, commit, метрики, bootstrap-интервалы).
  **Любая цифра на слайде воспроизводится этой командой**; цифры для питча — только
  `pitch/facts.md` со ссылкой на файл результата.

## Открытые источники (раздел 6; подробно — `research/SOURCES.md`)

- Все ответы внешних источников — через кеш на диске; демо работает на кеше без интернета.
- robots.txt и условия использования соблюдаем, паузы между запросами, защиту не обходим.
- Сопоставление с ИНН: реквизиты с сайта → реестр по названию и региону → ручная проверка выборки.
  Неразрешённая компания — «ИНН не подтверждён» (`inn=None`), а не угаданный ИНН.
- О физлицах, включая ИП, — только публичное из госреестров **[ПРОВЕРИТЬ 152-ФЗ]**.
- Пакетные задачи идемпотентны, пишут прогресс и продолжаются с места падения.

## Guardrails (раздел 13)

- Не выдумывай данные, метрики, контрагентов, контакты. Данных нет — так и скажи.
- Не переписывай модули других областей и замороженные контракты; правки — в зоне задачи.
- Ключи и токены — только `.env` (в `.gitignore`), шаблон — `.env.example`. Данные организаторов,
  кеш, индексы — вне git (`data/`, `cache/`, `indexes/`; страж — `check-data-files.sh`, > 5 МБ).
- Тяжёлые зависимости — только при необходимости и с записью в DECISIONS; всё в lockfile.
- «Работает» / «проверено» не пишется без команды и её вывода — ни в PR, ни человеку.
- Лучший следующий шаг — посмотреть данные, разметить 20 пар или разобрать ошибки? Делай его.
- Идентификаторы и комментарии в коде — английские; интерфейс и документы — русские.

## Git (кратко; полностью — `GIT.md`)

Задача → worktree `.claude/worktrees/<N>-<тема>` на ветке `worktree-<N>-<тема>` → PR в `main` с
`Closes #N` → перед push `git fetch --prune && git merge origin/main` и `make check` → merge после
вердикта `reviewer`, по одному (`gh pr merge <PR> --merge --delete-branch`). Не trunk-based: без
`pull --rebase`. Пушить агент может сам, в том числе в `main` (D-016); обычный путь в `main` —
PR. Запрещено (`permissions.deny`): force-push, `--no-verify`, удаление `main`, rebase,
`reset --hard`, `add -A`/`add .`, `commit -a`, amend. В коммит — только свои пути. Трейлеров
соавторства ИИ нет (`attribution` пустой).

живым демо?** Отрицательный эксперимент, за 10 минут закрывший тупик, ценнее 500 строк кода. Но 500
строк, которые не запускаются на демо, на защите стоят меньше нуля. **Если к 15:00 первого дня нет
end-to-end на данных организаторов — все бросают текущие задачи и доводят skeleton.**

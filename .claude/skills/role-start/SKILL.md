# Первые действия роли

Источник — раздел 15 (и 9 — research) `docs/source/hackathon-research-workflow.md`. Роль —
это метка `area:` и карта владения каталогами (`docs/project-structure.md`); у области есть
основной человек, но любой может взять свободную задачу чужой области.

**Каждый шаг ниже — только через взятую issue**: `bash scripts/issues.sh free area:<роль>` →
`take <N>` → worktree (скилл `orchestrate`). Нет задачи под шаг — `issues.sh create` по
`.github/ISSUE_TEMPLATE/task.md`, потом `take`. Время — по `docs/timeline.md` (МСК, 01.10);
`[ОБНОВИТЬ 01.10]` — после kickoff сверить с планом `docs/plans/<дата>-plan.md`.

Аргумент — роль. Без аргумента — спроси роль одной строкой и выведи её раздел.

| 2 | `DATA_DICTIONARY.md` v0 | поле → тип → пример → заполненность → смысл → уверенность → как проверили | 11:30 |

| 4 | Парсер → `data/processed/*.parquet`, склейка контрагентов по ИНН | тест на склейку; DuckDB читает | 13:00 |

| # | Шаг | Критерий выхода | К |

|---|---|---|---|

извлечение реквизитов с сайтов, entity resolution «название → ИНН».

# EVAL — оценка качества

Источник: раздел 7 `docs/source/hackathon-research-workflow.md`. Владелец — DATA; MATCH и SOURCES
запускают `make eval` после каждого изменения. Без eval нет ни research, ни цифр на слайде.

## A. Backtest на истории

Если в данных есть, кто подавал оферты или получал контракты (есть: таблица Поставщики — ИНН участников лота и `is_winner`, `research/PROBLEM.md`).

- Разбиение **по времени**: признаки — только по данным до даты D, запросы — из закупок после D.
  Случайный split даёт утечку.
- Запрос — позиция или закупка из тестового периода; релевантные — фактический поставщик и
  подавшие оферты (ЭМ: все оферты лота релевантны, победитель — grade 2; АИС ГЗ: в данных фактически только исполнитель — релевантен он; метрики считаем **раздельно по каналам**).
- Метрики: Recall@10, MRR, nDCG@10 (`src/eval/metrics.py`).
- Обязательные baseline: **популярность** (самые частые поставщики в классе ОКПД2) и **BM25**.
  Если мы их не обыгрываем — это главный вывод, а не мелочь. Baselines: популярность в классе ОКПД2, **история заказчика** (в 2025 г. 57.85% побед — у поставщика, уже побеждавшего у этого заказчика), BM25 — T-08 плана. Потолок recall на истории — доля холодного старта (dev 6.75%).
- Утечки: статистики контрагента не включают тестовую закупку; дубли склеиваются по ИНН до разбиения.
- Ограничение: backtest измеряет «угадали, кто и так участвовал», а не «нашли лучших». Поэтому нужен B.

## B. Ручная разметка новых поставщиков

Для 10–15 реальных запросов размечается top-10 блока «Новые из открытых источников»: 1 — компания
действительно поставляет или производит это, 0 — нет. Метрика — precision@10. LLM-судья может
доразметить остальное только после проверки согласия с человеком на пересечении (ориентир — не
ниже ~80%). Одна и та же модель не ранжирует и не судит одновременно.

Файл разметки — `eval/labels/new_suppliers.csv`:

```text
query_id,inn,name,label,labeled_by,labeled_at
stub-dev-1,0000100051,,1,человек:<логин>,2026-10-01T15:10
stub-dev-1,,ООО «…» (ИНН не подтверждён),0,llm:<модель>,2026-10-01T15:20
```

`inn` или `name` (если ИНН не подтверждён); `label` — 0/1; `labeled_by` — `человек:<логин>` или
`llm:<модель>`.

## C. Обогащение

Покрытие (доля кандидатов с подтверждённым ИНН, статусом, контактами) и точность на выборке из 30
контрагентов, проверенных вручную. Evidence-проверка (`src/enrich/evidence.py`) — обязательна для каждого факта.

## D. Реальные кейсы

5–10 реальных закупок заказчиков СПб из разных категорий: прогон целиком, скриншоты, разбор удач
и промахов. Прямой пункт 7 условий. Отбор кейсов — T-14 плана.

## Шум

На десятке запросов разница в пару пунктов — шум. `make eval` считает bootstrap-интервалы по
запросам (2000 выборок, фиксированный seed). Улучшение, которое держится на одном запросе, подозрительно.

## Как это устроено в коде

- `make eval EXP=<id>` → таблица в терминал и `eval/results/<id>.json`: `exp_id`, `part`,
  `created_at`, `commit`, `dirty`, `config` (`configs/search.yaml`), `config_sha256`, `stub`,
  `n_queries`, `metrics` (`value`, `ci95`), `per_query`. Любая цифра на слайде воспроизводится этой
  командой (`pitch/facts.md`). Id `final*` зарезервирован.
- Части — `configs/split.yaml`: `cutoff`, `holdout_from`, пути к кейсам. `dev` —
  `[cutoff, holdout_from)`, для настройки; `holdout` — с `holdout_from`, **запечатан**.
  Даты — `configs/split.yaml` (cutoff 2025-07-01, holdout 2025-10-01); сборщик — T-07; исключаем лоты без участников и АИС ГЗ с «ст.93»/«единственный поставщик».
- `src/eval/split.py`: `load_cases("holdout")` вне `make eval-final` бросает `SealedError`;
  кейс dev вне своих дат — ошибка «split leak».
- `make eval-final CONFIRM=<sha256>` (`src/eval/final.py`) читает holdout, только если:
  1. `CONFIRM` равен sha256 конфигурации (`configs/search.yaml` + `configs/split.yaml` + закоммиченный код метода `src/{match,enrich,sources,ingest,eval,llm}`, `src/contracts.py`; UI и API не входят, D-015); без
     `CONFIRM` команда печатает текущий хеш;
  2. дерево чистое для `src/ configs/ pyproject.toml uv.lock`;
  3. эта конфигурация на holdout ещё не запускалась;
  4. `search()` — не `# STUB`.
  Каждый запуск — строка в `eval/final-log.md`. Запускает только `evaluator` и только по заморозке.
- Тест замка — `tests/unit/test_eval_seal.py`.
- `make eval` оценивает ту же выдачу, что видит пользователь: после замены заглушки `evaluate()`
  прогоняет `strip_unverified()`, как `/api/search` (D-015).

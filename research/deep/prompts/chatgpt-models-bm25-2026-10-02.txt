Контекст: хакатон RLT.Hack (Росэлторг), 2 октября 2026, до feature freeze несколько часов (изменения — часы, не дни). Сервис подбирает поставщиков к лоту госзакупки Санкт-Петербурга (АИС ГЗ и Электронный магазин, 44-ФЗ ст. 93). Запрос — текст лота: короткие русские названия позиций (1–15 слов: «бумага для офисной техники А4», «перчатки нитриловые смотровые», «картридж HP CF259X», много аббревиатур, марок, ГОСТ). Поиск идёт по 1 031 361 уникальному нормализованному названию позиций из истории 2024–2025 (1 047 638 документов в индексе), затем найденные позиции агрегируются в поставщиков (ИНН) и скорятся формулой: product_fit 0.762 (= 0.8·BM25 + 0.2·глубина совпадения кода ОКПД2), experience 0.19 (лоты и победы поставщика среди похожих позиций), activity 0.048. Демо работает на CPU-ноутбуке (Intel Core Ultra, 16 ГБ RAM, без GPU), бюджет p95 ≈ 2 с на запрос; корпус можно перекодировать заранее на RTX 4080 16 ГБ.

Текущий стек ретривера: bm25s (Python, Lucene-вариант, k1=1.5, b=0.75 по умолчанию), токенизатор prefix5 (слово обрезается до 5 символов), BM25 top-500. Опционально «pg_hybrid»: + pgvector HNSW kNN top-1000 (ef_search=1000) по intfloat/multilingual-e5-small (384 dim, max_seq_length 128, префиксы «query: »/«passage: ») → Reciprocal Rank Fusion k=60. По умолчанию в продукте только BM25.

Наши замеры (temporal split, dev = лоты после 2025-07-01; метрики по реальным победителям лота; 95% bootstrap CI):
Ступень 1, 500 dev-запросов. cand_recall@200 — доля победителей среди 200 кандидатов-поставщиков; recall@10 — в топ-10 простого порядка ретривера.
- BM25 prefix5: полный текст лота 0.768 / recall@10 0.435; короткий запрос 0.737 / 0.403
- BM25 Snowball: 0.771 / 0.428; короткий 0.745 / 0.405. BM25 pymorphy3 (лемматизация): 0.768 / 0.436; короткий 0.742 / 0.408 (всё в пределах шума)
- Только вектор, полный текст: e5-small 0.600 / 0.301; rubert-tiny2 0.572 / 0.260; deepvk/USER-base 0.623 / 0.299 (на 0.15–0.20 хуже BM25)
- Только вектор, короткий запрос: e5-small 0.719 / 0.386; e5-base 0.722 / 0.376; rubert-tiny2 0.702 / 0.378; USER-base 0.739 / 0.404
- Гибрид RRF, полный текст: e5-small 0.757 / 0.377; tiny2 0.762 / 0.376; USER-base 0.769 / 0.398 (recall@10 НИЖЕ BM25 на 0.04–0.06)
- Гибрид RRF, короткий запрос: e5-small 0.743 / 0.398; e5-base 0.746 / 0.395; tiny2 0.738 / 0.396; USER-base 0.754 / 0.404 (единственный значимый плюс: +0.017 [0.006, 0.032] cand_recall@200)

Полный продукт, dev 2000 запросов, recall@10 / MRR / nDCG@10: порядок чистого BM25 0.449 / 0.358 / 0.344; текущий дефолт (BM25 + формула) 0.491 / 0.374 / 0.364; обученный LightGBM LambdaMART поверх тех же кандидатов (признаки компонент, обучен на 3000 запросах до 2025-04-01) 0.572 / 0.480 / 0.456; логистическая регрессия 0.551 / 0.458 / 0.434. Потолок кандидатов ≈ 0.77: ~23% победителей вообще не попадают в 200 кандидатов.

ТЕМА: лексический поиск и гибридное слияние — обоснован ли BM25 (bm25s, prefix5) + RRF k=60 и что улучшить за часы.
1. BM25 как baseline: BEIR, RusBEIR (2025), BRIGHT, Amazon ESCI / Shopping Queries — где dense/hybrid выигрывает у BM25 и насколько; почему BM25 силён на коротких запросах с редкими токенами/артикулами.
2. bm25s (Lù 2024): скорость против rank_bm25/Elasticsearch/Pyserini, варианты (Lucene, BM25+, BM25L, ATIRE), чувствительность к k1/b; что говорит литература про b и k1 для очень коротких документов (названия 3–10 слов, tf почти всегда 1).
3. Морфология русского для IR: усечение префикса, Snowball, лемматизация pymorphy, символьные n-граммы (Savoy, McNamee, RusBEIR и новее) — согласуется ли «все три варианта в пределах шума» с литературой.
4. Слияние: RRF (Cormack 2009) vs выпуклая комбинация нормированных скоров (Bruch, Gai, Ingber 2023, TM2C2), взвешенный RRF, выбор k и глубины списков; почему равновесный RRF ухудшает recall@10, когда одна ветка заметно слабее — объясни наш результат «гибрид на полном тексте хуже BM25 по recall@10 на 0.04–0.06 при почти равном cand_recall@200».
5. Learned sparse для русского (BGE-M3 sparse, SPLADE multilingual, OpenSearch neural sparse multilingual): цифры и оправданность за часы.
6. Наш главный разрыв — потолок кандидатов 0.77: какие приёмы расширения пула кандидатов (query expansion, псевдо-релевантная обратная связь RM3, поиск по ОКПД2-соседям, поставщики заказчика) работают в литературе и с каким эффектом.

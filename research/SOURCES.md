Проверка доступности, не парсинг: ≤ 5–7 запросов на хост, паузы ≥ 2 с (ЕИС — ≥ 60 с по
`Crawl-delay`), таймаут 15 с, User-Agent `Mozilla/5.0 (compatible; RLTHack-SourcesProbe/0.1;
hackathon availability check)`. Тестовые ИНН: 7707049388, 7804428656, 636200108061 (ИП).
Сырые ответы — в scratchpad агента, в git не кладём.

**TLS.** zakupki.gov.ru, estore.gz-spb.ru, gz-spb.ru выдают сертификат от «Russian Trusted Root
CA» (Минцифры): без него `curl: (60) SEC_E_UNTRUSTED_ROOT`. Решение — официальные PEM
`https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt` и `…/russian_trusted_sub_ca_pem.crt`;
в Python — бандл `certifi` + эти два сертификата (одного Минцифры мало: zakupki.mos.ru и др. — на
обычных CA). Это не обход защиты, а штатный корень доверия госсайтов РФ.

### Рекомендации

**(а) enrich(inn) к 13:30.** Основной источник — **pb.nalog.ru** («Прозрачный бизнес»): одна карточка
даёт статус, ОКВЭД, адрес, категорию МСП, ОГРН, капитал — и для ЮЛ, и для ИП. 4 POST на ИНН,
JSON, без ключа; ответ целиком кладём в `SourceCache` (значения буквально есть в теле → проходит
`evidence.py`). Самый простой запасной путь (1 запрос, без асинхронности): **bo.nalog.gov.ru**
`GET /advanced-search/organizations/search?query=<ИНН>` (статус, ОКВЭД2, адрес, выручка; только ЮЛ)
+ **rmsp.nalog.ru** `POST /search-proc.json` (категория МСП, ОКВЭД; ЮЛ и ИП). Если pb начнёт
требовать капчу (`captchaRequired:true`) — останавливаемся и переходим на bo+rmsp, капчу не решаем.
Реализовано (#10, D-026): `src/sources/pb_nalog.py` + `src/enrich/enrich.py`; Ростелеком 7707049388 — `rsmpcategory: 0` (не МСП), категория МСП — только 1–3.
РНП — отдельная проверка через ЕИС, не чаще 1 запроса в минуту, только для финального шорт-листа.

**(б) discovery v0 к 15:30.** **Реестр контрактов Электронного магазина**
`estore.gz-spb.ru/contracts/catalog/common/eshop?productOKPD2=<код>&productName=<слова>` →
участники с ИНН, по ним `enrich`. Новые для заказчика — те, кого нет в данных организаторов
(пересечение с выгрузкой организаторов проверить первым делом **[ПРОВЕРИТЬ]**). Медленно (13–15 с
на страницу) — только через кеш, прогрев заранее по ОКПД2 тестовых закупок. Следующий шаг (не v0):
поиск по ОКВЭД+региону в pb.nalog.ru / rmsp.nalog.ru (формы это поддерживают, запрос не проверен
**[ПРОВЕРИТЬ]**) — компании без истории госзакупок. ГИСП и поисковые API с площадки сейчас не
доступны.

**(в) Требует подтверждения человека (№4).** Ключи и регистрация: DaData (бесплатный тариф с
регистрацией), Checko, api-fns, 2ГИС API, Yandex Search API (Yandex Cloud, платно), токен
сервиса ЕИС через Госуслуги. Массовый обход реестра контрактов Эл. магазина или ЕИС — тоже
подтверждение (сначала подвыборка). ГИСП — проверить человеком в браузере и спросить
организаторов, не обходить WAF. 152-ФЗ: в реестре контрактов Эл. магазина участники — в том
числе физлица с 12-значным ИНН (самозанятые); берём только ЮЛ и ИП, подтверждённых ЕГРИП (`k=fl`
с ОГРНИП), остальных не показываем **[ПРОВЕРИТЬ 152-ФЗ]**.

## Сопоставление с ИНН — самое хрупкое место

Название на сайте не совпадает с названием в ЕГРЮЛ; у группы компаний несколько юрлиц. Порядок:

1. ИНН со страницы реквизитов на сайте;
2. поиск по названию и региону в реестре;
3. ручная проверка на выборке.

ИНН проверяется по контрольным цифрам (10 знаков — юрлицо, 12 — ИП; `inn_is_valid` в
`src/contracts.py`). Неразрешённая компания показывается с пометкой «ИНН не подтверждён»
(`inn=None`), а не с угаданным ИНН.

## Правила

- У каждого факта — источник, URL и дата получения (`Evidence`). В интерфейсе источник рядом с
  фактом. Факт без источника не показывается.
- LLM может **извлекать** данные из текста страницы, но не **порождать** их. ИНН, телефон, email
  или адрес, которых нет в тексте источника, — ошибка уровня блокера. Механически ловит
  `src/enrich/evidence.py` (значение буквально в тексте закешированной страницы + контрольные
  цифры ИНН); тест — `tests/unit/test_evidence.py`.
- Все ответы внешних источников кешируются на диск: `src/sources/cache.py` (SQLite, TTL,
  при падении сети — устаревший кеш). Демо работает на кеше, даже если упадёт интернет площадки.
- Уважаем robots.txt и условия использования, паузы между запросами, защиту не обходим.
  Заблокированный на площадке IP — мёртвый модуль.
- Собираем данные о компаниях. Персональные данные физлиц, включая ИП, — только то, что публично
  в госреестрах, без лишнего сбора **[ПРОВЕРИТЬ требования 152-ФЗ; вопрос для Q&A]**.
- Пакетные задачи (ночное обогащение) идемпотентны, пишут прогресс и продолжаются с места
  падения: очередь `src/worker/queue.py` + `make worker`.
- Массовый парсинг сайтов — подтверждение человека №4. Сначала подвыборка, потом весь объём.

## Research-спринты (раздел 9)

15–20 минут, не фоновый процесс. Когда: на kickoff, пока идёт профиль данных; когда застряли на
типе ошибок; перед питчем (аналоги). Не читать статьи, пока skeleton не работает. Для каждого
метода — ответ «почему это должно помочь **на наших данных**?». Нет ответа — не внедряем.

Что искать по ролям:
- **DATA:** руководства АИС ГЗ по Электронному магазину и Порталу 44 (смысл полей), методики обоснования НМЦК.
- **MATCH:** рекомендации поставщиков в закупках, supplier/entity matching, baseline популярности,
  классификация текста в ОКПД2, learning to rank.
- **SOURCES:** открытые данные ФНС и ЕИС, доступ к реестрам, поисковые API, извлечение реквизитов
  с сайтов, entity resolution «название → ИНН».
- **APP:** как заказчики работают в Электронном магазине, аналоги и конкуренты для слайда.

Формат записи — ровно три строки:

```text
R-01 | <ссылка>
     | Что применимо у нас: …
     | Стоимость: N ч
```

# ERROR_ANALYSIS — разбор ошибок

Источник: раздел 8 `docs/source/hackathon-research-workflow.md`. Владелец — DATA, с момента,
когда заработал eval. Обязателен после трёх экспериментов подряд без прогресса: 20–30 ошибок
(`per_query` в `eval/results/<id>.json`) → классы → новые гипотезы в `EXPERIMENTS.md`.

Типичные классы ошибок: неверный или слишком общий ОКПД2; общие наименования; дубли
контрагентов; неразрешённый ИНН; неактивные компании; посредник вместо производителя; промах по региону.

Команда `uv run python -m src.eval.lost <a> <b>` (#197) перезапускает `search()` на конфигурации, **записанной в `eval/results/<a>.json`** (`config`), а не на текущем `configs/search.yaml`: с D-077 дефолт — H-15f, а цифры строки «Скоринг выталкивает…» сняты на E-002 (v1). Другая конфигурация — `--config-of <id из configs/experiments.yaml>`. Если код метода изменился после прогона, `rerun_differs` в выводе показывает, у скольких кейсов top-k разошёлся с записью — тогда цифры воспроизводятся на commit из файла результата. Компонента с весом 0 (география с D-077) сравнивается, но наибольшим взвешенным проигрышем не бывает; равные баллы — `tie_by_inn` или `tie_by_bm25` по `options.tie_break`.

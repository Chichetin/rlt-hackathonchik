# Как считается балл: пайплайн, валидация, тяжёлые случаи

Состояние на 02.10.2026: `origin/main` + ветка `worktree-198-ranker`. Цифры — из `eval/results/*.json`,
`research/EXPERIMENTS.md`, `research/ERROR_ANALYSIS.md`; при написании не перезапускались.

**Главное:** в `main` балл = формула H-15f (D-077). Обученный ранжировщик (#198) — в открытых PR #274 и #309, не влит.

---

## 1. Из чего считаем

Три CSV организаторов, 2024–2025:

- **Извещения** — лот, дата, НМЦК, предмет, заказчик, канал ЭМ / АИС ГЗ;
- **Поставщики** — кто подал оферту, кто выиграл (`is_winner`);
- **ТРУ** — позиции лота и ОКПД2.

Нет названий поставщиков, цены контракта, расторжений, РНП → `reliability` и `price` в ответе есть, но
value 0, weight 0, «нет данных» (D-029). Не выдумываем — жюри видит в карточке, чего нет.

## 2. Пайплайн (один для API, eval, predict — `src/match/pipeline.py::pick`, D-097)

1. **Нормализация** (`src/match/text.py`): регистр, ё→е, слова и числа, без предлогов, слово → первые 5 букв
   («бумага/бумаги» → «бумаг»), кириллическая «А4» = латинская. Snowball / pymorphy — опции, только через eval.
2. **BM25** (`bm25s`, `src/match/index.py`): документ — уникальный текст позиции ТРУ или предмета лота с
   участниками строго до `as_of`; топ-500 документов. Почему BM25: прозрачно, быстро, обыграл baselines;
   `pg_hybrid` (pgvector + RRF) есть, включается только после выигрыша на eval (D-034).
3. **Свой лот исключается** (D-091): запрос `lot-N` не находит лот N (иначе его участники в топе «по ответу»).
4. **Кандидаты**: документы → лоты → участники; топ-200 поставщиков по лучшему BM25 своих лотов.
5. **ОКПД2 запроса**: из запроса, иначе голосование (D-045): 100 лучших текстов позиций голосуют кодами своих
   позиций с весом BM25; сначала группа `XX.XX`, затем код внутри неё; в объяснении «определён по похожим позициям».
6. **Компоненты** в [0, 1], у каждой строка объяснения:

| Компонента | Формула | Почему |
|---|---|---|
| `product_fit` | 0.8 · BM25/BM25лучшего + 0.2 · глубина ОКПД2 (код 1.0, XX.XX.XX 0.75, XX.XX 0.5, класс 0.25) | главный вопрос: поставлял ли именно это |
| `experience` | 0.5 · min(1, ln(1+лоты)/ln 21) + 0.5 · min(1, ln(1+победы)/ln 11) по лотам с похожими позициями | «поставлял это», а не «крупный в классе»; логарифм гасит гигантов |
| `activity` | 0.5^(дней с последнего участия / 90) | ответит ли на приглашение |
| `geography` | КПП в регионе заказчика 1.0, сосед 78↔47 0.8; **вес 0**, показывается | на рынке СПб не различает, штрафовала ИП |

7. **Балл**: `score = Σ weight · value`, веса 0.762 / 0.190 / 0.048 / 0, сумма 1 → сверяется с карточкой
   арифметикой. Равные — по BM25, затем по ИНН.
8. **Обогащение только из кеша**: статус, МСП, роль, название (ФНС, реестр МСП, ГИР БО); нет кеша → ИНН в
   очередь `worker`, поля «не проверено».
9. **Блок «Новые»** (`discover`) — раздел 5.
10. **Жёсткие фильтры** (`filters.py`): ликвидирован / банкрот / в РНП — убираем; статус неизвестен — не убираем.
11. **Фильтры пользователя**: МСП, роль, ЮЛ/ИП, регион, мин. релевантность; неизвестный признак — отбрасываем,
    UI пишет, у скольких неизвестен (D-030).
12. **`verified()` → `strip_unverified`**: показывается только факт, прошедший Evidence.

## 3. Почему такие веса

Каждая правка: экспертный старт (D-004) → backtest 2 000 dev-лотов со срезами (товары/услуги, ЭМ/АИС ГЗ,
новый/знакомый заказчику) → оставляем, если не хуже в целом и ни в одном срезе значимо → проверка на
2 000 свежих кейсах вне подбора.

| Конфигурация | recall@10 dev |
|---|---|
| v1 (экспертные веса) | 0.382 |
| B-bm25 (только текст) | 0.449 |
| H-15f / E-003 (`main`) | 0.491 [0.471, 0.511]; свежие кейсы 0.496 |

Разбор ошибок (`src.eval.lost E-002 B-bm25`): v1 выталкивал из топ-10 тех, кого BM25 ставил высоко
(313 из 2 000) — geography / experience / activity награждали крупного местного поставщика независимо от
запроса. Поэтому текст 0.762, география 0. Вес географии 0.05 хуже нуля и у товаров (−0.015 [−0.024, −0.007]),
и у услуг (−0.011 [−0.020, −0.002]) — профили по типу закупки есть, но выключены (D-099).

## 4. Ранжировщик #198 (PR #274, #309 — не в `main`)

- **Зачем**: участник среди 200 кандидатов в 76.8 %, в топ-10 — 49 %. Потеря — в порядке.
- **Признаки** (`src/match/ranker.py`, 43): компоненты, BM25 абсолютный и относительный, лоты/победы похожие и
  в группе, глубина ОКПД2, лоты у заказчика, давность, стаж, регион по КПП и ИНН, доля побед, профиль поставщика
  (#114), канал, доля в канале, ИП и др. NaN = не знаем.
- **Обучение без утечки** (`ranker_train.py`): запросы — лоты [2025-04-01, 2025-07-01), признаки строго до
  2025-04-01, метки оферта 1 / победитель 2 / иначе 0; ранняя остановка — 15 % обучающих запросов, dev не читается.
  Модели: LightGBM LambdaMART и логистическая регрессия.
- **Результат dev** (`D101-default`): recall@10 **0.572** [0.553, 0.592], MRR 0.480; турнир против v2:
  recall +0.081 [+0.068, +0.095], MRR +0.105.
- **Балл на экране** (#309): число = формула (сходится с карточкой), порядок = модель, `rank_reason` —
  «выше следующего, потому что…» по разнице SHAP. Сырой LambdaMART не шкала (лучший мог получить 0.24).
- **К4**: в карточке 3 признака «за» и 1 «против» с их значениями, вклады точные (tree SHAP). «Нет данных» не довод.
- Включение по умолчанию — подтверждение №3.

## 5. Новые компании, роль, Evidence

- **Discovery** (D-036): класс ОКПД2 → основной ОКВЭД. Совпал класс — «вероятно производитель»; оптовый 46.xx
  по ручной таблице `WHOLESALE` — «вероятно дистрибьютор». Источники: реестр МСП (вкл. офлайн-пул полной
  выгрузки, D-090), реестр контрактов ЭМ, веб-лиды (D-101: показываются, только если в кеше карточка ФНС
  и ОКВЭД / регион сходятся).
- **Роль** (D-057) по основному ОКВЭД: 10–32 производитель; 46.2–46.9 дистрибьютор; 45 (кроме 45.2), 46.1, 47 —
  дилер; 33, 45.2 — не определена. Основание — строка закешированной страницы с этим ИНН. В балл не входит.
- **Evidence** (`src/enrich/evidence.py`): у факта `url` и `fetched_at`, значение буквально в тексте страницы,
  ИНН с контрольными цифрами. Не прошло — не показывается. LLM извлекает, не порождает.

## 6. Валидация

- **Split по времени** (`configs/split.yaml`): история до 2025-07-01; dev июль–сентябрь 2025 (51 599 кейсов,
  в git выборка 2 000); holdout октябрь–декабрь 2025 (88 848).
- **Кейс** = реальный лот; релевантны ЭМ — все оферты (победитель grade 2), АИС ГЗ — победитель. Исключены
  прямые договоры (ч. 12 ст. 93), лоты без валидного ИНН.
- **Метрики**: recall@10, MRR, nDCG@10, bootstrap 95 % по запросам, парные сравнения (`src.eval.compare`).
- **Baselines**: B-pop (популярность в группе), B-inc (история заказчика), B-bm25.
- **Срезы**: канал, `winner=new/known` — сервис обещает находить незнакомых заказчику.
- **Holdout запечатан** (D-010, D-076): только `make eval-final CONFIRM=<sha256>`, чистое дерево, один запуск
  на конфигурацию, выборка 3 000 с фиксированным seed. **`eval/final-log.md` пуст.**
- **Backtest без кеша** (D-097): статус / РНП в кеше — факты сегодняшнего дня; что убрали бы сегодняшние
  фильтры — `today_filters`, вне метрик.
- **8 реальных кейсов** (`real.jsonl`, 4 ЭМ + 4 АИС ГЗ, 8 классов): recall@10 0.490 [0.240, 0.750] — демонстрация.
- **Блок «Новые»**: precision@10 по ручной разметке (`eval/labels/new_suppliers.csv`); LLM-судья — отдельный
  субагент, слепые пакеты, засчитывается при ≥ 20 общих пар и согласии ≥ 80 %.

## 7. Тяжёлые случаи

| Случай | Что делаем |
|---|---|
| По тексту никого (опечатка, латиница, редкий товар) | лестница отката (D-072): векторы → по ОКПД2 → подъём кода до класса; объяснение «как найден», BM25-часть = 0 |
| Пустой ответ | всегда с причиной: `X-Search-Note` |
| ОКПД2 не задан, предсказание ошиблось («калька» → калькуляторы) | голосуют позиции (D-045); «определён автоматически»; discovery по предсказанному классу в сеть не ходит |
| Код не совпадает с текстом | предупреждение и оба варианта, молча не заменяем (D-062) |
| Кривой код («1712», «17,12») | нормализуется; нераспознанный — отброшен с причиной |
| Запрос из самой закупки | лот исключён (D-091) |
| Все 1.00 (насыщение) | тай-брейк BM25; потолки опыта (D-093, ждёт №3); ранжировщик |
| ИП без КПП / КПП из нулей | вес географии 0; регион по ИНН — опция `inn_region` |
| Победитель новый для заказчика / холодный старт (6.65 % dev) | потолок backtest; блок «Новые», срез `winner=new` |
| Источник «Новых» упал | `X-Discovery-Error` и плашка (D-102) |
| Нет статуса / РНП | «не проверено», жёсткий фильтр не срабатывает |
| Невалидный ИНН | «ИНН не подтверждён», `inn=None` |
| > 20 000 символов / > 64 слов | 422 / 64 самых редких слова |
| Утечка во времени | `as_of = cutoff`; тесты `test_build_cases`, `test_eval_seal`; `as_of` от клиента — 422 |

## 8. Чего нет

- Holdout не запускался.
- Precision блока «Новые» и точность ролей не измерены.
- `price`, `reliability` не вычислимы на данных организаторов.
- Ранжировщик не влит (№3).
- Веса H-15f подобраны на том же dev; окончательно — только holdout.

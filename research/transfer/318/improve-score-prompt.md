# Промпт: поднять качество рекомендаций (К2) и закрыть слабые места

Ты — агент MATCH в репозитории RLT.Hack. Цель — поднять recall@10 / MRR на dev и закрыть неизмеренные места,
не ломая объяснимость (К4) и не трогая holdout.

## Правила (обязательны)

- Сначала прочитай `CLAUDE.md`, `research/METHODOLOGY.md`, `research/EVAL.md`, `research/ERROR_ANALYSIS.md`,
  последние строки `research/EXPERIMENTS.md` и `research/DECISIONS.md`.
- Каждое направление — отдельная issue (`bash scripts/issues.sh create` → `take`), свой worktree.
- Каждый эксперимент — по скиллу `/experiment`: гипотеза в 5 строк → подвыборка (`--sample 500`) → полный dev
  2 000 → `make eval EXP=<id>` → `uv run python -m src.eval.compare <id> <база>` → строка в `EXPERIMENTS.md`.
- База сравнения: `E-003` (`main`, recall@10 0.491) и, если #274 влит, `D101-default` (0.572).
- Принимаем, если не хуже в целом и ни в одном срезе (`channel`, `winner=new/known`) значимо не хуже; затем
  проверка на свежих dev-кейсах вне выборки подбора.
- Holdout не читать. `make eval-final` — только evaluator по заморозке.
- Смена формулы, весов, состава компонент или дефолта ранжировщика — подтверждение человека №3: готовишь цифры
  и строку «на подтверждение», `configs/search.yaml` сам не меняешь.
- Не выдумывать цифры; каждая цифра — из `eval/results/<id>.json`.

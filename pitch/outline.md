### Слайд 1. Больше половины закупок достаётся уже знакомому поставщику; в Электронном магазине 41% закупок — с одной офертой

### Слайд 2. Методология: прозрачный балл из вычислимых компонент (v2 — три в балле, география показывается)

- `score = Σ вес · значение`, каждая компонента в [0, 1], у каждой — строка объяснения.
- Считаются на данных организаторов 4 из 6; веса v2 (D-077): `product_fit` 0.762, `experience` 0.19,
  `activity` 0.048; `geography` показывается, вес 0 (максимум балла 1.0). До 01.10 вечера было 0.35 / 0.20 / 0.10 / 0.10.
- Не считаются: `reliability` и `price` (вес 0): у `price` нет цены контракта (есть только НМЦК); `reliability` считается в режиме
  shadow (D-157: показ в карточке, в балл и порядок не входит); статус — из кеша (F-38), РНП — из кеша (D-154).
- Жёсткие фильтры — отдельно от балла. Правило в коде есть (ликвидированное юрлицо и РНП — убрать) и срабатывает, когда
  факт известен: статус — из карточки ФНС / ГИР БО в кеше (F-38), РНП — из кеша, живая проверка РНП — отдельным
  проходом не чаще 1 запроса в минуту (D-154); нет проверки — в карточке «не проверено», охват РНП в выдаче [нет артефакта]. СМП, регион, производитель — по выбору пользователя.
- Планируем проверить (не сделано): `price` как близость масштаба закупки к типичной НМЦК поставщика;
  `reliability` из реестров для блока «Новые». Эти две правки **ждут подтверждения
  решения команды (№3)**; веса v2 подтверждены 01.10 (D-077).

Откуда: `research/METHODOLOGY.md` («Что вычислимо на наших данных», «На подтверждение человеку»),
веса — `configs/search.yaml`.

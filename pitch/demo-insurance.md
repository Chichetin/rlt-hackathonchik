# Страховка демо и запасное видео

Источник: разделы 10 и 12 («Страховка демо») `docs/source/hackathon-research-workflow.md`.
Проверяется скиллом `submission-checklist`.

## Страховка

- `make demo` поднимает всё одной командой с чистого клона и проверен **на той машине, с которой
  будет показ** (`[СПРОСИТЬ]` команда — какая машина).
- Демо-запросы и их результаты закешированы (`src/sources/cache.py`); демо не зависит от внешних
  API и Wi-Fi площадки.
- Запасное видео записано до code freeze (02.10, 16:30, `docs/timeline.md`).
- Никаких захардкоженных «красивых» ответов: жюри может попросить свой запрос.
- `# STUB` в демо-пути нет (`make stubs` после code freeze — ошибка).
- e2e демо-сценария зелёный (`make e2e`).

## Сценарий запасного видео (60–90 с)

Шаги — из `docs/ui.md` (тот же сценарий, что e2e `src/ui/e2e/demo.spec.ts`):

1. Ввести наименование товара или вставить позиции из ТЗ — реальная закупка СПб (демо-лот ЭМ из T-05).
2. Показать два блока: «С опытом госзакупок» и «Новые из открытых источников», score и
   объяснение в одну строку.
3. Открыть карточку: компоненты скоринга, факты с источниками и датами, контакты, тип
   (производитель/дистрибьютор), МСП, РНП.
4. Включить фильтр (только МСП / только производители / регион).
5. Выгрузить список в Excel.

Запись: разрешение 1920×1080, без звука или с короткой озвучкой; файл — `[СПРОСИТЬ Q-12]` куда
кладём (не в git, если > 5 МБ).
